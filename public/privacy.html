VOTRE RÉGIE, VOTRE PC

Confidentialité.

OpenMultiview ne possède pas de base centrale de configurations ni de comptes utilisateurs. Le multiview travaille avec vMix et le stockage de votre PC.

Réglages et stockage local

La configuration utilise le stockage de votre navigateur pour les écrans et les modèles. Le compagnon enregistre les réglages dans %LOCALAPPDATA%/multiview-vmix. L’identifiant de PC relie les pages à ces réglages sur votre propre ordinateur.

Le compagnon écoute sur 127.0.0.1, pas sur une interface réseau publique. Il accepte les pages locales et les origines HTTPS officielles déclarées dans le projet. Les signaux de connexion des écrans restent en mémoire et expirent après douze secondes sans mise à jour.

URL de rappel

Une URL complète contient des IDs de sources, les réglages d’habillage et l’adresse de l’API vMix. Toute personne qui reçoit ce lien peut lire ces informations. Les paramètres avant # sont transmis à l’hébergeur et peuvent apparaître dans ses journaux. Les réglages placés après # restent dans le navigateur et ne sont pas envoyés dans la requête HTTP.

Pour conserver ces requêtes sur votre PC, utilisez les pages locales du compagnon. La configuration et les affichages sont marqués noindex pour ne pas être proposés à l’indexation des moteurs de recherche ; cela ne constitue pas un contrôle d’accès.

Site public et services externes

L’accueil charge ses styles, son logo et sa démonstration depuis le même site. Le projet n’intègre pas de publicité, de mesure d’audience ou de police externe. Le stockage du navigateur sert au fonctionnement de la configuration et au choix de langue.

L’hébergeur peut traiter les données techniques nécessaires pour servir les pages, notamment l’adresse IP et les informations de requête. GitHub, Node.js et vMix appliquent leurs propres politiques lorsque vous suivez leurs liens. La démonstration de l’accueil ne contacte pas votre API vMix.

Code et contact

Le code est consultable sous licence MIT. Pour une question sur le fonctionnement ou les données, utilisez le dépôt du projet. Évitez de publier des données privées dans une issue publique ; les signalements de vulnérabilité disposent d’un canal privé sur GitHub.
